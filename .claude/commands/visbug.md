---
description: Анализирует правки VisBug и переносит их в CSS/стили проекта
---

Ты — **интегратор UI/CSS**. Интерпретируй визуальные правки из VisBug и переноси их в исходники: CSS, SCSS, CSS Modules, Tailwind или `<style>` — по стеку проекта.

## Шаг 1 — Получить правки

Вызови `get_changes` (MCP visbug-mcp) без фильтра. При длинном списке можно фильтровать: `style`, `attribute`, `text`.

Формат строк уже на русском, например:
`[3] .hero → стиль: top = 10px (было: 0px)`

## Шаг 2 — Отфильтровать шум

Игнорируй артефакты VisBug (drag, resize, внутренние классы):
- `transition: undefined`, `cursor: undefined`, `user-select: undefined`
- любое значение `undefined`
- `transform: translate(Xpx, Ypx)` с длинными дробями (случайный drag)
- смена `class` только из-за router-link-active / transition-классов фреймворка
- правки на контейнерах-обёртках, если VisBug сдвинул layout целиком — уточни у пользователя scope

## Шаг 3 — Понять намерение

| Правка VisBug | Вероятное намерение | Семантичное решение |
|---------------|---------------------|---------------------|
| `height: 304px` на карточках | одинаковая высота | `align-items: stretch` + `height: 100%` |
| `transform: translate(0, 12px)` | вертикальный сдвиг | `margin-top` / `translate` только если в дизайне так задумано |
| `font-size: 18px` | крупнее текст | токен типографики или переменная темы |
| `gap: 24px` | расстояние между элементами | `gap` / spacing token |
| `padding: 32px` | внутренние отступы | padding token |

## Шаг 4 — Где править (минимальный scope)

1. **Глобальный UI-компонент** (`.btn`, `.card`) — не ломать глобально; обернуть родителем страницы/секции.
2. **Компонент React/Vue** — правка в его CSS/модуле, внизу файла.
3. **Страница** — файл стилей страницы или секции.
4. **Токены/тема** — только если правка действительно глобальная.

Для Next.js / monochrom: предпочитай scoped CSS файлы (`hero.css`, `*.module.css`), не inline на контейнерах без нужды.

## Шаг 5 — План перед правкой

Для каждой значимой правки:

```
### [краткое название]
VisBug: селектор → свойство = значение
Намерение: …
Файл: путь к CSS
Селектор в коде: …
Правило: …
```

## Шаг 6 — Применить

1. Прочитать целевой файл.
2. Минимальный diff — только нужные свойства.
3. Не трогать тексты из CMS/Directus, если пользователь не просил.
4. После записи в код — `apply_changes` (все или по индексам `[N]` из вывода).

## Жёсткие запреты

- не хардкодить px там, где в проекте есть токены
- не править глобальные компоненты ради одной страницы
- не использовать `!important`
- не переносить случайные `top/left` с контейнеров, ломающие scroll/layout
- не оставлять ответы/комментарии на французском — только русский
